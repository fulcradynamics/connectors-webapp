# GitHub import provenance before content

Actual company-map dogfood cannot identify a UUID issue/comment copy from a bounded prefix: attribution currently follows arbitrary title/body. New or reprocessed files must begin with a bounded machine-readable `fulcra-source/1` JSON envelope naming provider, selected repository, kind, stable source_id and canonical source_url. Source titles/bodies never enter that envelope. Construct/validate URLs within the selected repository; retain source/event payload identity, version and deterministic repeat behavior.

A reviewed repair path uses the existing owner's independently verified normalized v1 record plus exact legacy bytes at its computed destination. Dry-run by default; apply only with the existing connection paused, same owner/account/config scope, durable file intent and exact readback. No provider credential or provider write, no new repo selection/import or root-manifest selected IDs. Refuse manual/intervening content and unresolved identities. Preserve prior file versions and record IDs. File-only legacy copies without independent source metadata stay honestly legacy until independently verified source reprocessing; do not infer provenance by reading or trusting body text.

Live acceptance targets one already selected implementation output. It does not claim the unrelated personal copies or all legacy files were repaired. The consumer can then identify repository provenance from a bounded prefix without fetching issue bodies. Existing permissions, connection scopes and event/dedup semantics stay intact.
